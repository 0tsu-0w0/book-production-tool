# tategumi

縦書き（と横書き）の組版ソフト（Windows / Mac）。原稿を入力すると文庫判の縦書きページをその場で組み、
入稿用 PDF（PDF/X-1a または PDF/X-4・CMYK・トンボ付き）と画像に書き出す。要件定義書の機能（フェーズ1〜3）をひととおり入れ終えた。

## 動かし方

Node.js 22 以降が必要。

```bash
npm install
npm start          # 画面を開く
npm test           # テスト
npm run pdf        # 画面を開かずに見本の原稿を入稿用 PDF（out/sample.pdf）にし、PDF/X-1a の検査をする
npm run pdf -- 文書.tategumi 出力.pdf            # 入稿用（PDF/X-1a:2003・CMYK・トンボ付き）
npm run pdf -- 原稿.txt 出力.pdf --no-marks      # 入稿用（トンボなし）
npm run pdf -- 原稿.txt 出力.pdf --screen        # 閲覧用（RGB）
```

## インストーラーを作る（NF-08）

コード署名はしていない（費用がかかるため）。そのため、初めて開くときに OS の警告が出る。

```bash
npm run dist:win   # Windows：release/tategumi-setup-<版>.exe（Windows で実行する）
npm run dist:mac   # Mac：release/tategumi-<版>-mac.dmg（Intel と Apple Silicon の両方で動く。Mac で実行する）
```

- Windows のインストーラーは、インストール先を選べ、管理者の権限はいらない。デスクトップにショートカットを作り、.tategumi 文書を関連付ける（ダブルクリックで開く）。
- Mac のアプリは簡易署名（ad-hoc）だけする。完全に署名なしだと、Apple Silicon の Mac では「壊れている」と出て開けないため。
- 開くときの警告：
  - Windows：「Windows によって PC が保護されました」→「詳細情報」→「実行」。
  - Mac：アプリを右クリック →「開く」→「開く」。それでも開けなければ、ターミナルで `xattr -cr /Applications/tategumi.app`。
- フォルダの場所が長い（260 字に近い）と、Windows のインストーラー作り（NSIS）が「could not find ... .nsh」で止まる。短い場所（例：`C:\work	ategumi`）に置いて作る。
- アイコンは `build/icon.png`（1024px）。画面の言語は日本語と英語だけを入れて、大きさを減らしている。

### 速さと大きさ（0.4.1 時点。10万字・287ページの文書、Windows）

- 1文字直してからプレビューが描き直されるまで：中央値 約0.13秒（組版 約55ms・受け渡し 約15ms・描画 約50ms）。
- 起動：同梱のフォントで組むときは PC のフォントを調べない。PC のフォントの一覧は控え（ユーザーデータの font-cache.json）を使い、2回目からは 0.5秒 → 0.04秒。
- 配布物：アプリ本体（app.asar）約27MB、インストーラー約105MB（大部分は Electron）。依存関係のうち使わない部分（ブラウザー用の束・型・ソースマップ・MathJax の HTML 出力や読み上げなど）は package.json の build.files で外している。

## スタイルの記法

```text
［＃引用］この行には段落スタイル「引用」が当たる
これは［＃太字］強調したい言葉［＃／太字］です
```

- 行頭の［＃名前］（同じ行に［＃／名前］がないもの）は段落スタイル。見出し（＃・＃＃）には大見出し・中見出し、ほかの行には本文が当たる。
- ［＃名前］…［＃／名前］で囲んだ文字には文字スタイル。閉じ忘れは行の終わりで閉じる。行頭の［＃名前］が文字スタイルの名前なら、その行全体に当たる。

## ページ操作の記法

```text
［＃改ページ］      次のページから（＝＝＝ と同じ）
［＃改丁］          次の奇数ページから（偶数ページに当たれば白ページを入れる）
［＃白ページ］      白ページを1枚入れる
［＃扉］
＃第一章　灯り
［＃／扉］          間の行を1ページにまとめて、ページの中央に置く（章扉など）
［＃目次］          見出しから作った目次を入れる（新しいページから）
［＃画像：名前］                  画像を版面に収めて1ページに置く
［＃画像：名前　全面］            ページ全面（塗り足しまで）に置く
［＃画像：名前　5行］             本文の中に5行分の幅で置く（天・中央・地を足せる）
［＃画像：名前　5行　回り込み］   画像の上（天なら下）に本文を回り込ませる
［＃画像：名前　切り抜き：上10下10　大きさ：80%　ずらす：右2下3　キャプション：庭の猫（筆者撮影）］
［＃表］ … ［＃／表］           表（「| 欄 | 欄 |」の行。「|---|」より前は見出しの行）
［＃ラベル：名前］               この場所に名前を付ける
［＃ページ：名前］               そのラベルのあるページ番号
｜文字《白ゴマ》                   圏点（ほかに 丸・白丸・二重丸・蛇の目・三角・白三角。《圏》はゴマ）
｜文字《傍線》                     傍線（ほかに 二重傍線・波線・点線・破線）
［＃割注］注の文字［＃／割注］      割注
［＃縦中横］2B［＃／縦中横］        縦中横（2〜3桁の数字と !? などは自動）
```

- 扉の閉じ忘れは、次の改ページで閉じる。1ページに収まらない扉は、ふつうの本文として流し込む。
- 改ページ・改丁・白ページ・扉・目次・画像は、スタイルの名前に使えない。
- 目次は段落スタイル「目次の題」「目次の項目1」「目次の項目2」で組む。
- 本扉は段落スタイル「書名」「著者名」、奥付は「奥付」で組む（書体や大きさはスタイル欄で変えられる）。

## 構成

| 場所 | 役割 |
| --- | --- |
| `src/engine/` | 組版エンジン（整形・記法の読み取り・行とページの割り付け・ページ要素・字形の割り当て）。画面から独立していて Node.js だけで動く |
| `src/document/` | 文書ファイルの形式と、設定（既定値・字組のプリセット・和色・古い設定の読み替え） |
| `src/fonts/` | PC のフォントの一覧、.ttc からの取り出し、フォントの読み込み |
| `src/output/` | PDF（PDF/X-1a・PDF/X-4・トンボ・色の変換）と、その検査。ICC プロファイルの読み取り（`icc.ts`）。CFF フォントの埋め込み（`cff-font.ts`） |
| `src/fonts/cff.ts` | CFF の読み書きと縮小（使っていない字形を空にする。字形番号と CID の対応は変えない） |
| `src/main.ts` / `src/pdf-worker.ts` | Electron の本体（メニュー・ファイル・復元・PDF の書き出しスレッド） |
| `src/renderer/` | 画面（原稿欄・プレビュー・設定欄）と、画像の書き出し（Worker） |
| `assets/fonts/` | 同梱フォント（Noto Serif JP、SIL OFL）とライセンス。作り方と出どころは [assets/fonts/README.md](assets/fonts/README.md) |
| `scripts/make-test-doc.mjs` | 確認用の文書（MVP の機能をひととおり使う）を作る |

画面・PDF・画像は、同じ組版結果（`DrawPage`）を描くので、どれで見ても改行位置が同じになる。

## わかっている制限

- **PostScript 系（CFF）の .otf は、CID 方式のものだけ PDF に書き出せる。** 日本語の .otf はほとんどが CID 方式。
  CID 方式でない CFF フォントは、書き出すときにエラーを出す。
  CFF の縮小では、使っていない字形の中身を空にするだけで、字形の部品（Subrs）はすべて残す。そのためフォントによっては PDF が大きくなる（あかずきんポップで3ページ 241KB）。
- 可変フォント（Noto Serif JP の VF など）は一覧に出さない。
- TrueType フォントの PDF では、文字は取り出せる（コピー・検索できる）が、読み順が横向きになる。CFF フォントの PDF では読み順どおりに取り出せる。
- Mac では動作を確かめていない（Mac のインストーラーもまだ作っていない）。
- 背幅の紙の厚さは一般的な目安。実際の背幅は印刷所の計算で確かめる。
- 数式は MathJax（Apache-2.0）の TeX の記法で組む（base・ams・newcommand・boldsymbol）。数式の中の和文（\text{日本語}）は描けない（数式の外に書く）。行の中の高い数式（行列など）は、前後の行に重なることがある。
- TeX の記法は LaTeX の文書を読むためのもので、マクロの定義（\newcommand の文書全体での展開）や表（tabular）、相互参照（\ref・\label）、脚注には対応していない。
- PDF/X-1a・PDF/X-4 の検査は自作（PDF/X-4 は pdfinfo でも PDF/X-4 と判定されることを確認）。Acrobat のプリフライトや印刷所での確認はしていない。
